# integrations — ตัวเชื่อมต่อกับระบบข้างนอก

LINE, MOPH Notify, LLM ในเครื่อง, Core Backend, ฐานข้อมูลภายนอก ฯลฯ — แต่ละโปรเจกต์ใช้ไม่เหมือนกัน จึงไม่ใส่ในแกน
**1 ตัวเชื่อมต่อ = 1 โฟลเดอร์** ใช้เฉพาะตัวที่โปรเจกต์ต้องใช้ ที่เหลือไม่ต้องมีอยู่ในโปรเจกต์เลย

## กติกา

1. ทิศทาง: **หน้า (pages) → ตัวเชื่อมต่อ → แกน (core)** แกนห้าม import ไฟล์ในโฟลเดอร์นี้
2. ค่าลับ (token, secret, รหัสผ่าน) อยู่ใน `.env` เท่านั้น — ไม่เก็บในฐานข้อมูล ไม่แก้จากหน้าเว็บ ไม่เขียนลง log
3. ทุกตัวมีโหมดตาม `<NAME>_MODE` (`integrations/mode.ts`): `real` | `fake` | `off`
   - `fake` = ไม่ยิงออกข้างนอก แค่บันทึกว่า "จะส่งอะไรไปที่ไหน" (กัน LINE/MOPH ส่งถึงคนจริงตอนพัฒนา) · `production` ใช้ `fake` ไม่ได้
4. ทุกตัวมี `status()` ที่ตรวจว่าต่อได้ไหมโดย **ไม่ส่งข้อความหาคนจริง และไม่เปลี่ยนข้อมูลปลายทาง** — หน้า "สถานะการเชื่อมต่อ" เรียกใช้
5. error ที่ผู้ใช้เห็นเป็นภาษาไทย บอกว่าติดอะไร ต้องตรวจตัวแปรไหน (ดูตัวอย่างใน `llm/LlmClient.ts`)
6. ตั้งเวลาจำกัดการเรียกเสมอ (timeout) — ปลายทางค้างต้องไม่ลากระบบเรา

## โครงโฟลเดอร์ของตัวเชื่อมต่อ 1 ตัว (ดูแบบจาก `llm/`)

```
integrations/<ชื่อ>/
  <ชื่อ>Client.ts    คุยกับระบบข้างนอก (fetch / SDK) + status()
  index.ts           export ตัวใช้งาน (เช่น llm) และ <ชื่อ>Integration สำหรับหน้าสถานะ
```

แล้วต่อ import + รายการใน `integrations/index.ts` และเพิ่มตัวแปรของมันใน `.env.example` (ใส่คำนำหน้า `<NAME>_` ทุกตัว)

## ที่มีในตัวกลาง

| ตัว | ใช้ทำอะไร |
|---|---|
| `llm/` | คุย LLM แบบ OpenAI-compatible (Ollama, LM Studio, vLLM) |
| `core_gateway/` | ขอข้อมูลโรงพยาบาลจาก Backend Core (token อัตโนมัติ, retry, โควตา) — ดู docs/07 |
| `core/datasource.ts` (แหล่งข้อมูลอ่านอย่างเดียว) | ต่อฐานข้อมูลของระบบอื่น เช่น HOSxP — `readonlyDb('hosxp')` |

LINE / MOPH Notify ยังไม่อยู่ในตัวกลาง — เพิ่มเมื่อมีระบบที่ใช้จริง โดยทำตามรูปแบบเดียวกับ `llm/`
