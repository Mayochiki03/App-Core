# 06 — ตัวเชื่อมต่อ และฐานข้อมูลภายนอก

บางระบบต้องคุยกับของข้างนอก: LLM ในเครื่อง, LINE, MOPH Notify, Core Backend, ฐานข้อมูล HOSxP — ตัวกลางมีที่ทางให้ โดยแกนไม่ผูกกับตัวไหนเลย

## ตัวเชื่อมต่อ (`backend/src/integrations/`)

อ่านกติกาที่ `backend/src/integrations/README.md` สรุปสั้น ๆ:

- 1 ตัว = 1 โฟลเดอร์ ใช้เฉพาะที่ต้องใช้
- ค่าลับอยู่ใน `.env` ใช้คำนำหน้าตามชื่อ เช่น `LLM_BASE_URL`
- มีโหมด `real` / `fake` / `off` — ตอนพัฒนาตั้ง `fake` เพื่อไม่ให้ข้อความหลุดไปถึงคนจริง
- ดูสถานะที่เมนู ระบบ > สถานะการเชื่อมต่อ (เฉพาะ ADMIN)

### ตัวอย่าง: ใช้ LLM ใน Service

```ts
import { llm } from '../../integrations/llm';

const answer = await llm.chat([{ role: 'user', content: 'สรุปข้อความนี้ให้สั้น' }]);
```

ตั้งค่าใน `.env` (Ollama):

```
LLM_BASE_URL=http://127.0.0.1:11434
LLM_MODEL=ชื่อโมเดลที่ pull ไว้
LLM_TIMEOUT_SEC=120
```

ยังไม่ตั้ง `LLM_BASE_URL` = ปิดอยู่ (เรียก `llm.chat` จะได้ข้อความภาษาไทยบอกให้ตั้งค่า)

## ฐานข้อมูลของระบบอื่น (อ่านอย่างเดียว)

ใช้กับ HOSxP และฐานข้อมูลอื่นที่เป็นของคนอื่น ใช้ร่วมกับระบบอื่น และเปิดใช้งานสดอยู่ — **ห้ามใช้ `db` หลักต่อ** ให้ใช้ `readonlyDb`:

```
# .env  (ตั้งชื่อแหล่งเองได้ ที่นี่ชื่อ hosxp)
HOSXP_DB_HOST=192.168.x.x
HOSXP_DB_NAME=ชื่อฐานข้อมูล
HOSXP_DB_USER=ผู้ใช้ที่มีสิทธิ์ SELECT อย่างเดียว
HOSXP_DB_PASSWORD=...
```

```ts
import { readonlyDb } from '../../core/datasource';

const rows = await readonlyDb('hosxp')('patient').select('hn').limit(10);
```

สิ่งที่ตัวกลางทำให้:
- เซสชันเป็น READ ONLY ที่ฝั่งฐานข้อมูล — insert/update/delete/สร้างตารางล้มเหลวแม้ user มีสิทธิ์เขียน (มีเทสต์พิสูจน์)
- ไม่มี migration และไม่เคยแตะตารางในนั้น
- pool เล็ก (สูงสุด 5) และจำกัดเวลา query (`HOSXP_DB_QUERY_TIMEOUT_SEC` ค่าเริ่มต้น 30 วินาที) เพื่อไม่ให้ฐานข้อมูลของคนอื่นช้าเพราะเรา
- แสดงสถานะการต่อบนหน้า "สถานะการเชื่อมต่อ" ให้เอง

อย่างไรก็ตามควรขอ user ฐานข้อมูลที่มีสิทธิ์ SELECT อย่างเดียวด้วย — READ ONLY ของเซสชันเป็นชั้นป้องกันที่สอง ไม่ใช่ชั้นเดียว
