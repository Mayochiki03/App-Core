# 02 — อ่านโค้ดทีละขั้น: กด "บันทึก" 1 ครั้ง โค้ดวิ่งไปไหน

วิธีอ่านโค้ดที่ง่ายที่สุดคือ **ตามรอยคำสั่งจริง** เริ่มจากปุ่มที่กดไปจนถึงฐานข้อมูล แล้วกลับมาที่หน้าจอ
ตัวอย่างนี้คือหน้า "เพิ่มคู่ค้า" (`/vendor/add`)

## ฝั่งหน้าเว็บ

0. **`config/routes.tsx`** — `{ path: '/vendor/*', element: <VendorPage /> }` ส่งทุก URL ที่ขึ้นต้น `/vendor` ไปที่ `VendorPage`
   แล้ว **`pages/vendor/VendorPage.tsx`** แยกต่อเป็น `VendorTable` / `VendorAdd` / `VendorEdit`
1. **`pages/vendor/VendorAdd.tsx`** — ฟอร์มกับปุ่ม กด "บันทึก" → `handleSave`
   - ตรวจช่องกรอกตามกติกาใน `VendorForm.tsx` (ช่องว่าง = ขีดแดงทันที ยังไม่ยิง API)
2. **`vendorApi.add(values)`** (`api/vendorApi.ts`) — บรรทัดเดียว `api.post('/vendor/add', body)`
3. **`api/client.ts`** — ยิง `fetch('/api/vendor/add', { method: 'POST', body })` แล้วแปลงคำตอบเป็นรูปแบบเดียวเสมอ `{ ok, status, message, data, fields }` (ไม่ throw)

## ฝั่งหลังบ้าน

4. **`vite.config.ts`** (ตอน dev) ส่งต่อ `/api/*` ไปพอร์ต 4000 · ตอน production หลังบ้านเสิร์ฟทั้งคู่เอง
5. **`backend/src/app.ts`** — `api.use('/vendor', requireAuth, requireRole(...), router)`
   - `requireAuth` (`core/auth.ts`) ตรวจ cookie → รู้ว่าใครเรียก · `requireRole` ตรวจสิทธิ์ตาม `roles` ของหน้า
   - `auditMiddleware` (`core/audit.ts`) แอบจดไว้ว่า "ใครทำอะไร" ตอนตอบเสร็จ
6. **`VendorController.ts`** — `router.post('/add')` → `parse(vendorSaveDto, req.body)` ตรวจข้อมูลด้วย DTO (ผิด = โยน error 400)
7. **`VendorService.ts`** — `create()` เช็ครหัสซ้ำ (ซ้ำ = โยน `conflict` 409) แล้วสั่ง Repository
8. **`VendorRepository.ts`** — `insert()` เขียนลงฐานข้อมูลด้วย knex แล้วคืน id
9. กลับขึ้นไปที่ Controller → `res.json(ok({ id }))`
10. ถ้ามี error โยนขึ้นมาที่ชั้นไหนก็ตาม → **ตัวจัดการ error กลางใน `app.ts`** ตอบรูปแบบ `{ status, message, fields }` ให้เอง

## กลับมาที่หน้าจอ

11. `VendorAdd` ได้ผลลัพธ์:
   - `res.ok` → `popup.success(...)` แล้ว `navigate('/vendor')`
   - `DUPLICATE` / `VALIDATION` → `applyFieldErrors` ขีดแดงช่องที่ผิด + `popup.warn`
   - อย่างอื่น → `popup.error(res.message)`

## ชื่อเดียวกันตลอดทาง

ฟิลด์ `code` เป็นชื่อเดียวกันในฟอร์ม → body ที่ส่ง → DTO ของ backend → คอลัมน์ในฐานข้อมูล ไม่มีการแปลงชื่อ
อยากรู้ว่า "ช่องนี้ไปไหนบ้าง" → ค้นชื่อนั้นทั้งโปรเจกต์ (Ctrl+Shift+F) จะเจอครบทุกชั้น

## ทำไมไม่มี id ใน URL

ทุก API เป็น POST และส่งข้อมูลทั้งหมดใน body — เพราะ URL ถูกจดไว้ใน log ของเซิร์ฟเวอร์/พร็อกซี/ประวัติเบราว์เซอร์ ข้อมูลที่ไม่ควรเปิดเผย (id, ชื่อ, คำค้น) จึงไม่ควรอยู่ใน URL
หน้าแก้ไข (`/vendor/edit`) รับ id จาก state ของ router: `navigate('/vendor/edit', { state: { id } })`
การค้นหารายการ (`/search`) ไม่ถูกบันทึกใน audit log เพื่อไม่ให้ log ท่วม ส่วนเพิ่ม/แก้/ลบ/เปิดดูรายละเอียด (`get`) บันทึกทุกครั้ง

## โซนของไฟล์ (ควรแก้ตรงไหน)

| โซน | ไฟล์ | แก้ได้ไหม |
|---|---|---|
| เขียว ที่ทีมทำงาน | `backend/src/pages/*`, `frontend/src/pages/*`, `frontend/src/api/*Api.ts`, `config/routes.tsx`, `config/menu.ts`, `lib/messages.ts` | แก้/ก๊อปได้เลย |
| เหลือง ปรับให้เหมาะกับงาน | `components/*` (หน้าตา component กลาง, `layout/`), `theme.css`, `.env` | แก้ได้ ระวังกระทบทุกหน้า |
| แดง ตัวกลาง | `backend/src/core/*`, `api/client.ts`, `lib/session.tsx`, `hooks/*` | ปกติไม่ต้องแตะ — ถ้าจะแก้ ให้หัวหน้าทีมดู |

เปิดไฟล์ในโซนเขียว แล้วไม่เข้าใจ ไม่ต้องไล่ลง แดง — ทุกไฟล์มีคอมเมนต์หัวไฟล์บอกหน้าที่และวิธีใช้
